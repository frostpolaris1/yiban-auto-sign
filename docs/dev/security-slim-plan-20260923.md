# 安全与告警瘦身计划（2026-09-23，v2 按用户取舍修订）

> 背景：防护体系按公网多租户 SaaS 标准建设，摩擦成本超过威胁收益。目标：**合理放宽安全验证、
> 缩减无关安全功能、减少告警邮件、简化功能体系**——砍防护过度，不砍真防护。
> **规模校准（用户 2026-09-23 确认）：百人以上真实多用户**（09-23 实查：账号 89 / 用户 110，
> 09-22 单日新注册 21，增长快）。这推翻了「小站可大胆删」的假设：**鉴权、IDOR 防护、隐私脱敏、
> 审计全部保留**，瘦身集中在「摩擦体验」与「告警噪音」两块。
> **核心设计输入（用户 2026-09-23）**：硬门禁尽量换**软性摩擦**——风控式加验、后台验证留痕、
> 加载动画/倒计时拉长操作时间来降低误操作风险，而不是要求输口令打断体验。

---

## 0. 分级原则与红线（v2 修订）

| 级 | 判据 | 处置 |
|----|------|------|
| **红线不碰** | 防真实攻击/数据丢失/隐私泄露 | 保留原样 |
| **软摩擦替代** | 防误操作/会话滥用，但硬门禁体验差 | 换软性摩擦（倒计时/风控/事后告警） |
| **参数放宽** | 阈值造成误伤 | 改参数 |
| **无关防护** | 无人使用、场景不存在 | 删除 |
| **告警收敛** | 通知价值 < 打扰成本 | 并入摘要或删除 |

**红线清单（不许动）**——因规模百人以上，比 v1 更宽：
①账号凭据 AES-GCM 静态加密（`account_crypto.py`）；②`.env` 窄行写入防行注入（`env_io.py`）；
③CSRF + 防 session 固定；④SSRF 白名单（`notify/config.py:91-140`）；⑤last-admin 防自锁；
⑥易班锁号冷却（保护真实账号）；⑦凭据熔断 + 分级重试预算；⑧**审计链 HMAC + 锚点 + audit_verify**
（用户明确要留：审计取证校验）；⑨**session sid 吊销/轮换**（用户明确要留：改密即踢旧登录）；
⑩tracking 加盐哈希（百人级真实手机号/IP 的隐私保护，与审计配套）；⑪注册/登录/IDOR 防护全套
（多用户防滥用是真需求，巡检证实现有限速有效拦截且不影响自然增长）；⑫时延拉平防枚举（微小，留）。

## 1. 放宽安全验证（治 UX 摩擦）

### 1.1 口令复核门 → 软性摩擦替代（本计划最大 UX 收益）

**现状**：13 类操作要求当次输管理员口令（scrypt 比对）：改他人凭据、purge/彻底删除、重置他人口令、
改角色、删用户、关通道、改 SMTP/收件人/推送密钥、改设置 A/B 档、发公告、执行体写、急停。
另有豁免 TTL 300s、复核冷却 300s、失败计数告警。

**用户确认**：此项碍事，勾选大幅放宽。设计输入：「走风控、后台验证、靠加载动画拉长时间等操控来减少风险」。

**改法（软性摩擦三件套替代口令输入）**：
1. **倒计时确认**（替代输入口令）：危险操作前端弹「此操作不可逆，N 秒后可确认」倒计时确认框
   （加载动画拉长时间的落地形态），后端要求请求带 `confirm_delay_ack` 且距上次危险操作 ≥ 间隔——
   防手滑连点，不打断心流；
2. **事后告警**（替代事中口令）：改他人凭据、purge 两类最高危操作保留**异步告警**
   （一封「刚才执行了 XX 操作」的通知，事后可追溯可回滚）；
3. **风控式加验**（替代一律加验）：仅异常态升级——同 IP 短时多次危险操作、非常用设备、
   操作频率超常时才要求口令复核（`YIBAN_PW_GATE=risk`，**建议默认**）。

档位：`off`（全软摩擦）/ `risk`（**默认**，异常才要口令）/ `full`（现状，保留兼容）。
连带：豁免 TTL/复核冷却/门禁失败计数告警仅在 `full` 下启用。

**测试影响**：`test_sensitive_gate_94`、`test_web_security_gates`、`test_switch_password_gate`、
`test_executor_write_guard`、`test_settings_tiers_94`、`test_credential_write_gate_94`、
`test_account_abuse_gate`、`test_role_hardening_0905`——按档位语义重写。

### 1.2 手动签到冷却 1800s → 同号 60s + 全局 10 次/600s（用户已拍板）

**现状**：`YIBAN_BATCH_SIGN_COOLDOWN_SEC` 默认 1800s 全局共用（`signin_api.py:161,260`）。
**改法**：默认 60s（与 `SIGN_MIN_INTERVAL` 对齐），加全局速率上限 10 次/600s 可配（防被盗会话刷真实登录）。
**测试影响**：`test_batch_sign_cooldown`、`test_batch18_knife2_0905`。

### 1.3 登录失败锁定放宽（用户确认碍事）

**现状**：同 (IP,用户名) 失败 5 次锁 300s（`auth.py:156-176`）。
**改法**：改 10 次→锁 60s（防暴力破解仍有效——巡检里真实攻击主要靠 nginx 边缘限速拦）。
登录频率 10/60s 保留。

### 1.4 高危操作额度放宽

5 次/60s → 20 次/60s（`app.py:624`）。软摩擦化后此项只是防脚本滥用的保险丝。

### 1.5 告警邮件（用户确认「刷屏」，全删管理操作类）

见 §3。

## 2. 缩减无关安全功能（v2 大幅收缩——规模校准后多数保留）

**v1 曾列的删除项经用户取舍后处置**（百人以上规模 + 用户明确取舍）：

| 项 | v1 计划 | v2 定案 | 理由 |
|----|---------|---------|------|
| 审计链 HMAC+锚点+audit_verify（1,300 行） | 降级普通日志 | **保留原样** | 用户勾选「审计取证校验」要留；百人级用户纠纷/滥用取证是真需求 |
| tracking 加盐哈希（133 行） | 删 | **保留** | 真实手机号/IP 隐私保护，与审计配套 |
| session sid 吊销/轮换（150 行） | 删 | **保留** | 用户勾选「改密即踢旧登录」 |
| 时延拉平防枚举 | 删 | **保留** | 百人级用户枚举有一定风险，成本为零 |
| **rekey 密钥轮换工具链**（720 行工具 + 2,871 行测试） | 移入 attic | **删除/attic**（用户未勾选） | 十年一遇场景，git 历史可考 |
| **clock_guard 时钟守卫**（约 300 行状态机） | 简化 | **简化**（用户「不清楚有没有可能触发，没见过」）：保留跳变告警 + 暂停清理一轮（几行判断），删冻结状态机、`clock_guard_reset.py`、欠账追踪 | 从未触发过，但防误删留个保险丝 |

**净缩减**：约 3,600 行（rekey 为主）+ clock_guard 状态机。比 v1 的 5,000+ 少——这是规模校准的正确代价。

## 3. 减少告警邮件（用户确认「刷屏」）

**现状**：几乎每个管理操作都发信（改设置/删用户/改角色/软删/注册/通道变更/摘收件人各有告警），
一天 5~10 封。另有每日通道健康日报。

| 事件类 | 现状 | 改后 |
|--------|------|------|
| 管理操作告警（改设置/删用户/改角色/软删/注册/通道变更/收件人摘除） | 逐条即时 | **删除**（日志页可查；§1.1 的事后告警只留最高危两类） |
| 登录失败告警 | 3 次即发 | 阈值 3→10（巡检证实 09-22 一天 9 封全是用户自己改密码的误报） |
| 高危口令门失败告警 | 即发 | 随 §1.1 档位，非 `full` 不发 |
| 签到失败（管理员汇总） | 收尾一封 | **保留**（核心运行报告） |
| 单账号耗时/容量超载/探针预警/窗口配置异常 | 各自独立成封 | **并入**收尾汇总信正文段落 |
| 用户签到失败信 / 审核拒绝信 | 即发 | **保留**（用户价值） |
| 通道健康日报 | 每日 | **改周报 + 降级即时** |
| 推送额度耗尽补发 | 即发 | 并入周报 |
| **备份失败哨兵（新增，巡检 B4）** | **无**（静默 4 天） | **新增**：每日 08:05 检查当日包存在，缺失→发一封告警（有节流）——这是「该有声音的故障」，与删噪音不矛盾 |
| SMTP 失败降级 webhook | urgent+force | 保留（真故障必须送达） |

**连带**：notify 三本账简化为一本 + urgent 标记；`urgent_only` 默认 0→1；巡检 B4 的 root crontab
MAILTO/备份行失败发声一并做。

**测试影响**：`test_alert_channel_dispatch`、`test_mail_notify`、`test_mail_failover_0907`、
`test_soft_delete_alert_0910`、`test_notify_throttle`、`test_notify_ledger_*`、`test_account_abuse_gate`。

## 4. 简化功能体系

### 4.1 设置 A/B 档合并
保留「仅主管理员」权限判定（A 档键仍限主管理员），口令要求统一随 `YIBAN_PW_GATE` 走；
急停双角色语义保留（安全件）。前端控件禁用逻辑随之简化。

### 4.2 在线验证体系——v2 改为保留
**v1 曾拟删异步任务体系，规模校准后推翻**：生产「账号提交即时验证已开启」、百人级用户持续
添加账号，验证是活功能；且「后台验证」正是用户软性摩擦思路的一部分（后台慢慢验，不阻塞提交）。
只做小幅精简：无人走的 cancelled/超龄收口分支合并。

### 4.3 配置面与文档瘦身
删掉的告警类对应配置项标注废弃；`docs/dev/` 相关文档同步。
